# Quests

Publish authored quest content as 38 public pages. Link each quest to the placed characters that it names. Publish phases, objectives, journal text, and rewards from typed data.

## Problem

The current compendium has 2,228 detail pages. Of these pages, 307 have no inbound link. People are the worst group.

There are 121 placed-character pages and 212 character pages. Nothing in the extracted data points at a character. A character is only ever the source of an edge today. A quest is the first authored source that names a character.

This slice adds quest pages and the quest-to-character relationship. It also publishes the authored content that gives each page reader value.

## Measured game data

The live game contains 38 `QuestData` assets. Every asset has a non-empty `questID` and `questName`. The assets have 38 distinct asset names.

The planning documents record 13 quests. That number is the subset registered in `BuiltLookupTable`, not the total asset count. Only those 13 assets have a lookup GUID. Quest identity therefore uses the asset name through the `namedAsset` mechanism:

```text
named;quest;<assetName>
```

The game stores these authored quest flags and values:

- 16 quests have `disabled` set.
- 11 quests have `hideInQuestUI` set.
- 2 quests set `simpleOnStartJournalEntry`.
- The source fields are `questID`, `questName`, `questSubname`, `disabled`, `hideInQuestUI`, `simpleOnStartJournalEntry`, `simpleOnSucceedJournalEntry`, `simpleOnFailureJournalEntry`, `requiredCharacters`, `objects`, `phases`, `rewardSets`, `flowGraph`, `events`, `macros`, `variables`, `termSets`, and `comments`.

The game contains 98 `QuestPhase` rows and 190 `QuestObjective` rows across the 38 quests. A phase has `phaseID`, `phaseName`, `journalEntry`, `completedJournalEntry`, and `questObjectives`.

An objective has `objectiveID`, `objectiveName`, `objectiveInfo`, `journalEntry`, `successJournalEntry`, `failureJournalEntry`, `type` of `ObjectiveType`, `hidden`, `attachedObjectID`, and `enableMapMarker`.

The quest objects contain these measured counts:

| object type | count | measured fields | published use |
| --- | ---: | --- | --- |
| `CharacterQuestObject` | 88 | `characterRecord`, `objectID`, `objectName`, `category` | Publish a character row and a character edge |
| `LocationQuestObject` | 139 | `locationPosition`, `locationRotation`, `locationMap`, `radius` | Do not publish in this slice |
| `JournalQuestObject` | 74 | `journalEntry`, `objectID`, `objectName` | Publish a journal-entry row |
| `CharacterGroupQuestObject` | 18 | authored object data | No settled public table in this slice |
| `SimpleDialogSceneQuestObject` | 17 | authored object data | No settled public table in this slice |
| `StaticReferenceQuestObject` | 10 | authored object data | No settled public table in this slice |
| `MultiTeleportQuestObject` | 7 | authored object data | No settled public table in this slice |
| `TimePeriodQuestObject` | 3 | authored object data | No settled public table in this slice |
| `ItemSpawnerReferenceQuestObject` | 1 | authored object data | No settled public table in this slice |
| `ScheduledEventQuestObject` | 1 | authored object data | No settled public table in this slice |

All 88 `CharacterQuestObject` entries resolve. None is null or missing. Each entry contains a `CharacterRecordContainer`. Its `record` is a `RecordReference`. The resolved character identity is `instances;characters;<32 hex>`, which matches the identity of the existing placed-character entity.

Quest rewards occur inside `rewardSets[].questRewards`:

| reward type | count | source fields |
| --- | ---: | --- |
| `XPQuestReward` | 20 | `xpAmount`, `customXPAmount` |
| `FactionRepQuestReward` | 21 | `faction`, `amount`, `isPositive`, `customReputation` |
| `GoldQuestReward` | 18 | `customGoldAmount` |
| `CharacterRepQuestReward` | 13 | `questObjectId`, `amount`, `isPositive`, `customReputation` |
| `ItemsQuestReward` | 4 | `itemLists`, `items`, `itemListLevel` |

The game maintains an internal object graph. Each `objects[].objectID` is referenced by `QuestObjective.attachedObjectID` and by `CharacterRepQuestReward.questObjectId`. Preserve these game IDs as references. Do not use them as row identity.

## Published identity and routes

The entity ID is `quest`. The identity mechanism is `namedAsset`. The canonical identity is `named;quest;<assetName>`.

Publish one route for each asset at `/quests/<slug>`. The route slug comes from the normal site slug convention. The quest asset name remains the identity input. The quest game ID remains a game reference in `quest_game_id`.

Publish all 38 quests. Do not filter a quest because `disabled` or `hideInQuestUI` is set. Show both flags as facts on the page.

If a future source has no quest name, publish `Unnamed quest`. Do not hide the quest and do not replace the name with an identifier. Emit one extraction diagnostic for the missing name.

## Canonical tables

The descriptor at `entities/quest/entity.json` is the only cross-subsystem source of truth for this entity shape. The pipeline emits SQLite tables from that descriptor. The site reads the emitted SQLite data.

Every table ID is generated by this project and is `NOT NULL`. Foreign table IDs are also `NOT NULL`. Game IDs are references, not row identity. The tables use explicit columns and typed sparse reward fields. They do not use a raw Unity, Odin, reflected-game, or catch-all JSON column.

## Extraction and presentation contracts

The mod emits a `QuestSnapshotFields` object with these named fields:

```text
id: string
questGameId: string
name: string | null
subname: string | null
disabled: boolean
hiddenInQuestUi: boolean
journalOnStart: string | null
journalOnSucceed: string | null
journalOnFailure: string | null
requiredCharacterRefs: SnapshotRef[]
phases: QuestPhaseSnapshot[]
characters: QuestCharacterSnapshot[]
journalEntries: QuestJournalSnapshot[]
rewardSets: QuestRewardSetSnapshot[]
```

The nested snapshot fields preserve source values and game references:

- `QuestPhaseSnapshot` has `phaseGameId`, `name`, `journalEntry`, `completedJournalEntry`, and ordered `objectives`.
- `QuestObjectiveSnapshot` has `objectiveGameId`, `name`, `info`, `journalEntry`, `successJournalEntry`, `failureJournalEntry`, `objectiveType`, `hidden`, `attachedObjectGameId`, and `enableMapMarker`.
- `QuestCharacterSnapshot` has `objectGameId`, `objectName`, `category`, and `characterRef`.
- `QuestJournalSnapshot` has `objectGameId`, `objectName`, and `journalEntry`.
- `QuestRewardSetSnapshot` has `setGameId`, `setName`, `setType`, and ordered `rewards`.
- `QuestRewardSnapshot` has `kind`, `isPositive`, `amountLabel`, `customAmount`, `factionRef`, `itemRefs`, `itemListRefs`, and `targetObjectGameId`.

The canonicalizer generates project row IDs. It uses each phase ID and objective ID as the stable game reference. It preserves source order with ordinals. It does not use game IDs as project row IDs.

The pipeline emits `quest_presentation_rows` with these columns:

| column | meaning |
| --- | --- |
| `id` | Quest row identity |
| `name` | Quest name |
| `subname` | Quest subname |
| `render_context` | `quest-presentation-v1` |
| `disabled` | Disabled flag |
| `hidden_in_quest_ui` | UI-hidden flag |
| `journal_on_start` | Reader-facing start journal text |
| `journal_on_succeed` | Reader-facing success journal text |
| `journal_on_failure` | Reader-facing failure journal text |
| `phases_json` | Ordered phases with ordered objectives |
| `rewards_json` | Ordered reader-facing rewards |

`phases_json` contains each phase name, journal entry, completed journal entry, and ordered objectives. Each objective contains its name, info, journal entry, success and failure journal entries, objective type, and hidden flag.

`rewards_json` contains ordered entries with these named fields:

```text
kind: gold | experience | faction-reputation | character-reputation | items
amount: string | null
targetLabel: string | null
targetRoutePath: string | null
items: { label: string; routePath: string | null }[]
```

The read model resolves every reference to a label and route path before it reaches the site. `amount` is reader-facing prose. It substitutes the custom integer when the source enum selects a custom amount. `targetLabel` and `targetRoutePath` identify faction reputation and character reputation targets. A null route means that the target has no page. The site states the target in plain text rather than creating a link. `items` is empty except for item rewards.

The site renders the presentation rows. It does not resolve references and does not turn enum values into prose. The presentation contract prevents unavailable names from spreading into pages.

## Relationships

Register these predicates in `pipeline/src/relationships/registry.ts`. The relationship registry is the single source for forward and inverse labels.

| predicate | source | target | forward label | inverse label | measured result |
| --- | --- | --- | --- | --- | --- |
| `features_character` | quest | NPC | `Characters` | `Appears in quests` | 88 edges |
| `rewards_faction_reputation` | quest | faction | `Faction reputation` | `Reputation from quests` | Up to 21 edges |
| `rewards_item` | quest | item | `Item rewards` | `Rewarded by quests` | Up to 4 reward sets |

The character predicate emits one edge for each resolved `CharacterQuestObject`. All 88 measured entries resolve, so the published snapshot has 88 character edges.

Faction reputation edges use the faction reference from `FactionRepQuestReward`. Emit an edge when that typed reference resolves. The measured reward count gives an upper bound of 21 edges.

Item reward edges use the typed item references from `ItemsQuestReward`. The measured data has four item reward sets. Do not infer item links from prose, graph data, or item lists without an explicit resolved reference.

## Page content

Each quest page states the quest name, subname, disabled flag, UI-hidden flag, and authored journal fields. It shows required character references when present.

Each page shows phases in source order. Each phase shows its name, journal entry, completion journal entry, and objectives in source order. Each objective shows its name, information, journal entries, objective type, hidden flag, attached object game ID when present, and map-marker flag.

Each page shows named quest characters and journal entries in source order. Character rows link to the placed-character pages. Journal rows display their authored text.

Each page shows reward sets and reader-facing rewards. The page states experience, faction reputation, gold, character reputation, and item rewards from the corresponding reward classes. The pipeline resolves amounts, labels, and routes before rendering.

A disabled quest still has a page. The page states that the game marks it as disabled. A quest hidden from the game quest UI still has a page. The page states that the game hides it from that UI.

## Deliberate exclusions

Do not walk or publish the Odin `flowGraph`, `events`, `macros`, `variables`, or `termSets`. These fields are runtime plumbing. Every reader-facing quest fact in this slice already exists in a typed list. Publishing the internal graph would add a second public link graph and duplicate those facts. `comments` also remains authoring data, not reader-facing quest content. Runtime progress in `QuestInstance` remains out of scope.

Do not publish the 139 `LocationQuestObject` entries. These entries have `locationPosition`, `locationRotation`, `locationMap`, and `radius`. They carry a coordinate and a radius, not a named place. A location link requires the game's containment test. That is a separate design decision.

Do not store those coordinates. Data that no reader or pipeline query uses is data that this project deletes. No location table or coordinate JSON column is part of this slice.

Other measured quest-object kinds have no settled typed public table in this slice. Their counts remain evidence about the game, not rows in the canonical tables.

## Acceptance

- The snapshot publishes 38 quest rows and the site publishes 38 quest pages.
- Quest identity uses `named;quest;<assetName>`. It does not depend on lookup registration.
- The snapshot publishes 98 phase rows and 190 objective rows with stable ordinals and preserved game IDs.
- Quest pages show phases and objectives in source order with their authored fields.
- The snapshot publishes resolved character rows for all 88 `CharacterQuestObject` entries.
- The relationship graph publishes 88 `features_character` edges. Character pages show the inverse `Appears in quests` relationship.
- Quest pages state typed experience, faction reputation, gold, character reputation, and item rewards.
- Presentation rows carry `render_context` equal to `quest-presentation-v1`.
- Faction and item reward relationships use the declared predicates and resolve only explicit typed references.
- A disabled quest remains published and shows its disabled flag.
- A quest with `hideInQuestUI` remains published and shows its UI-hidden flag.
- No snapshot contains raw Odin or Unity JSON, an untyped catch-all details column, or the 139 location coordinates.
- The site renders quest routes from pipeline-emitted SQLite data.
