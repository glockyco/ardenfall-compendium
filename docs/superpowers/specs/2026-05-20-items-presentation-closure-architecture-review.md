## 1. Verdict on the pivot

The pivot is right only if you redefine it from “literal transitive closure” to “every deterministic, user-facing dependency required to make item pages and item-linked pages complete.” Items already depend on status effects, spells, enchantments, stat types, categories, tags, recipe data, icon colors, and master-tooltip vocabulary, so a pure item-only patch will keep leaking placeholders and wrong labels; but a literal closure would also drag in runtime-only assets like weather, spawned characters, factions, timer assets, audio, FX, and meshes that do not belong in an item-first slice. Bundle the existing local presentation bugs into the same cut—icon tint drop, generic `status-effect` placeholders, variant-slug type lines, and broken spell target extraction—because those failures are in the current builder/site wiring, not in missing transitive entities. (`site/src/lib/components/items/ItemEffectList.svelte:15-20`; `site/src/lib/components/items/ItemIcon.svelte:2-26`; `mod/src/Entities/Item/ItemPresentationBuilder.cs:10-16,32-45,151-216`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/StringTooltip.cs:54-74,90-204`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/AddEffectOnWeatherEffect.cs:9-15`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/StatusEffectTooltipSpellEffect.cs:10-21`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/Item/TriggerOnDamageEnchantmentEffect.cs:10-21`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/Item/TimedEnchantmentEffect.cs:7-15`)

## 2. Scope corrections

- Use **deterministic presentation closure** as the boundary. Include fields and refs that `StatusEffectTooltip`, `SpellTooltip`, `EnchantmentTooltip`, item type/requirements/stat rows, icon colors, or recipe naming actually consume; do **not** commit Slice 4.5 to first-class `Weather`, `CharacterData`, `Faction`, `TimeRangeAsset`, `GameObject`, audio, or camera/FX assets just because some effect class touches them. (`.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/StatusEffectTooltip.cs:17-35`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/SpellTooltip.cs:28-70`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/EnchantmentTooltip.cs:33-62`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/AddEffectOnWeatherEffect.cs:9-15`; `/tmp/item-inventory.md:381-384,452-460,523-535`)
- `master-tooltip` should be a **private pipeline singleton**, not a public graph node or page. The current pipeline type and fixture only model tooltip codes/colors, and the read-model stage consumes them only to translate rich text and derive term edges; that is a support contract, not user-facing content. It is still a hard prerequisite because `StringTooltip.ApplyColors`, `SpellData.GetTooltip`, and `ArdenfallMasterData.ApplyColorCodes` all depend on it. (`pipeline/src/types.ts:187-190`; `fixtures/synthetic/snapshot/master-tooltip.json:1-10`; `pipeline/src/stages/emit-read-models.ts:179-204,304-341`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/StringTooltip.cs:54-74`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/SpellData.cs:223-237`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/ArdenfallMasterData.cs:229-268`)
- Bundle the already-proven **local defects** into Slice 4.5 instead of pretending they depend on new entity extraction: `displayIconColor` is captured from the mod and persisted into both overview and presentation rows, but `ItemIcon.svelte` ignores color; `ItemEffectList` renders the generic effect-fact labels that produce the `Status effects status-effect` placeholder; `ItemPresentationBuilder` falls back to title-cased variant ids for type lines, hardcodes `Armor` and `Mana cost multiplier` instead of the game’s `Damage Threshold` and computed `Mana Usage`, and looks for nonexistent `spellDataJson.name/id` keys even though the snapshot exports `spellName` and `spellRef`. (`mod/src/Entities/Item/ItemIconSlots.cs:43-47,74-83`; `pipeline/src/stages/emit-read-models.ts:72-79,216-223`; `site/src/lib/server/read-models.ts:306-307,348-349`; `site/src/lib/components/items/ItemIcon.svelte:2-26`; `site/src/lib/components/items/ItemEffectList.svelte:15-20`; `site/src/lib/components/items/ItemHeader.svelte:8-13`; `mod/src/Entities/Item/ItemPresentationBuilder.cs:10-16,32-33,151-216`; `mod/src/Entities/Item/Adapters/ItemAdapterHelpers.cs:88-97,238-247`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/Item/ArmorItem.cs:115-120`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/Item/SlateSpellItem.cs:236-240,416-421`)
- Treat item-side enrichment as **variant-specific catch-up**, not uniform rework. Bow and throwing-item adapters already serialize most tooltip-adjacent numeric fields plus status-effect refs, while melee and equipment/armor remain thin; the work is concentrated in `EquipItemData`, `MeleeItemData`, and the presentation builder, not evenly across every subtype. (`mod/src/Entities/Item/Adapters/ExtractBow.cs:14-34`; `mod/src/Entities/Item/Adapters/ExtractThrowingItem.cs:15-37`; `mod/src/Entities/Item/Adapters/ExtractEquipment.cs:12-17`; `mod/src/Entities/Item/Adapters/ExtractMelee.cs:10-16`; `mod/src/Entities/Item/Adapters/ExtractArmor.cs:9-15`)
- Do not reopen **note-text capture** as part of this pivot. The current adapter already emits both free-form `noteText` and structured `noteSectionsJson` with `textContent`, image refs, and separators, so any remaining note work is page/presentation work, not missing extraction. (`mod/src/Entities/Item/Adapters/ExtractNote.cs:17-42`; `mod/src/Entities/Item/Adapters/ItemAdapterHelpers.cs:187-199`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/Item/NoteItem.cs:11-25`)
- For the ~60 effect leaf types, the hard boundary is **“anything a live asset template can read by `componentIndex` + `variableName`, plus anything a `GetSubTooltip(s)` override emits”**—not every runtime-only member. The asset scan matters because the game chooses fields by string name, and some subclasses contribute no tooltip text unless a template references them. (`/tmp/item-inventory.md:359-360,523-535`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/StatusEffectTooltip.cs:20-35`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/SpellTooltip.cs:35-70`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/EnchantmentTooltip.cs:36-58`)

## 3. Sequencing plan

1. **Expand the private master-tooltip snapshot contract first.** `StringTooltip.ApplyColors` needs duration/target/positive/negative colors and tooltip code dictionaries, `SpellData.GetTooltip` needs `primarySpellTooltip`, `secondarySpellTooltip`, and `spellSubEffectColor`, and `ArdenfallMasterData.ApplyColorCodes` adds the separate term-set regex/link pass that the current `MasterTooltipDictionary` and fixture do not carry. (`.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/StringTooltip.cs:54-74`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/SpellData.cs:223-237`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/ArdenfallMasterData.cs:229-268`; `pipeline/src/types.ts:187-190`; `fixtures/synthetic/snapshot/master-tooltip.json:1-10`; `pipeline/src/rich-text/rich-text-v1.ts:37-40,79-90,242-264`)
2. **Land `stat-type`, `item-category`, and `item-tag` next, with public pages ready before item links point at them.** Items already carry `categoryRef` and tag ids, `EquipItemData` already carries `minimumSkill` plus a lossy `statType` string, and the real labels/descriptions/icons live on these small ScriptableObjects; shipping them early removes several item-page fallbacks without opening a whole new combat-entity track. (`mod/src/Entities/Item/Adapters/ExtractItem.cs:78-110`; `mod/src/Entities/Item/Adapters/ExtractEquipment.cs:12-17`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/StatType.cs:7-27`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/ItemCategory.cs:211-217`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/Item/ItemTag.cs:6-11`)
3. **Land `status-effect` before any spell or enchantment public relinking.** Consumables and throwing potions already point at status-effect refs, `StatusEffectData.GetTooltip` is the base composer, and both spell sub-tooltips and enchantment sub-tooltips recurse into status effects. (`mod/src/Entities/Item/Adapters/ExtractConsumable.cs:22-25`; `mod/src/Entities/Item/Adapters/ExtractThrowingPotion.cs:20-25`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/StatusEffectData.cs:124-181`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/StatusEffectTooltipSpellEffect.cs:16-21`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/Item/StatusEffectEnchantmentEffect.cs:62-69`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/Item/TriggerOnDamageEnchantmentEffect.cs:38-49`)
4. **Then land `spell`; `spell` is blocked on both the master-tooltip contract and status-effect parity.** Slate items consume spell name, icon, icon color, mana cost, type label, prefixes, and sub-tooltips, and `SpellTooltip` mixes primary/secondary levels plus subspell indexing. (`.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/Item/SlateSpellItem.cs:193-240,283-286,416-421`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/SpellData.cs:142-237`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/SpellTooltip.cs:28-70`)
5. **Land `enchantment` after `status-effect`, in parallel with or immediately after `spell`.** Equip items are currently missing both static enchantment arrays, and enchantments recurse into status effects, other enchantments, and item-target overrides. (`mod/src/Entities/Item/Adapters/ExtractEquipment.cs:12-17`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/Item/EquipItem.cs:164-181,331-332,437-450`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/Item/EnchantmentData.cs:58-83`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/EnchantmentTooltip.cs:33-62`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/Item/TimedEnchantmentEffect.cs:24-29`)
6. **Land `potion-recipe` after `status-effect` and `item-tag`.** Recipe names derive from the first produced potion’s effect name, and ingredients are tag-based. (`.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/Item/PotionRecipe.cs:13-39`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/Item/RecipeItem.cs:8-18`; `mod/src/Entities/Item/Adapters/ExtractPotionRecipe.cs:17-33`)
7. **Only then re-cut item presentation and relationship sections.** The current graph audit fails any edge whose target is missing or non-public, so item pages should not emit links until every target page is already public; this is also the point to replace the current builder heuristics and placeholder effect facts. ## 4. Composer architecture recommendation

Use a **pipeline-side TypeScript port** as the source of truth. Port `StatusEffectTooltip.GetTooltip`, `StringTooltip.GetValueFromField`, `SpellData.GetTooltip`/`SpellTooltip.GetTooltip`, and `EnchantmentData.GetTooltip`/`EnchantmentTooltip.GetTooltip` into a shared TS library, but execute it in the pipeline and persist `rich_text_v1` plus structured facts into read models. The pipeline already owns rich-text translation, term-link extraction, graph diagnostics, and static read-model emission, while the site only consumes the emitted JSON; moving the composer to the site would couple prerendering to raw snapshot DTOs and duplicate graph/diagnostic responsibilities. (`.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/StatusEffectTooltip.cs:17-35`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/StringTooltip.cs:90-204`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/SpellData.cs:173-237`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/SpellTooltip.cs:28-70`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/Item/EnchantmentData.cs:58-83`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/EnchantmentTooltip.cs:33-62`; `pipeline/src/stages/emit-read-models.ts:179-204,216-240,304-347`; `site/src/lib/server/read-models.ts:337-365`; `site/src/routes/items/[id]/+page.server.ts:13-20`)

Do not stop at `StringTooltip.ApplyColors`. The pipeline-side port also has to absorb the master-data term-set/link pass from `ArdenfallMasterData.ApplyColorCodes`, because the current rich-text translator only knows tooltip codes/colors and `<link="tooltip_...">` markup; term-set regex application is a separate step in the game. (`.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/ArdenfallMasterData.cs:229-268`; `pipeline/src/rich-text/rich-text-v1.ts:37-40,79-90,117-169,242-270`)

## 5. Effect-subclass representation recommendation

Choose **(a): one ordered, type-tagged effect-instance collection**, backed by a discriminated union DTO per concrete subclass. Concretely: store `owner_type`, `owner_id`, `owner_scope` (`status-effect`, `spell`, `subspell`, `enchantment`), `effect_index`, `effect_kind`, and a validated subtype payload JSON; emit graph edges from the payload separately. The composer wants “the Nth heterogenous effect on this owner” because templates dereference by `componentIndex`, `subspellEffectIndex`, and string `variableName`, so per-subclass tables make traversal and indexing awkward. Purely loose JSON blobs without a shared effect-instance table weaken audits, diffs, and reverse-edge extraction. (`.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/StatusEffectTooltip.cs:20-30`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/SpellTooltip.cs:35-68`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/EnchantmentTooltip.cs:36-58`; `/tmp/item-inventory.md:359-360`)

Normalize **outbound refs and page-summary fields**; keep purely runtime leaf data in the subtype payload until a public page or query needs it. That preserves future headroom without forcing you to relationalize every particle prefab, camera kick, or AI-only knob today. (`/tmp/item-inventory.md:523-535`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/AddEffectOnWeatherEffect.cs:9-15`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/Item/TimedEnchantmentEffect.cs:7-15`)

## 6. Graph/reverse-edge recommendation

Keep **one atomic `entity_edges` row per observed fact** and materialize both forward and reverse `entity_relationship_sections` from that same edge set. Add composite indexes on `(source_type, source_id, predicate)` and `(target_type, target_id, predicate)`; keep deterministic `edge_id`s; encode role/source-field/slot in `evidence_json`; and **do not** insert separate inverse edges. The current site already loads prebuilt sections by source node, so the cheapest reverse pages are target-side sections generated from the same canonical edge table, not a doubled edge corpus. (`pipeline/src/relationships/relationship-graph.ts:33-53,85-117`; `pipeline/src/stages/emit-read-models.ts:167-171,282-341`; `site/src/lib/server/read-models.ts:367-383`)

Recommended predicate vocabulary:

- `item -> status-effect : applies_status_effect` for `ConsumableItemData.statusEffects`, `ThrowingPotionData.areaOfEffect`, `StatusEffectEnchantmentEffect.statusEffect`, and `TriggerOnDamageEnchantmentEffect.applyStatusEffects`. (`mod/src/Entities/Item/Adapters/ExtractConsumable.cs:22-25`; `mod/src/Entities/Item/Adapters/ExtractThrowingPotion.cs:20-25`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/Item/StatusEffectEnchantmentEffect.cs:62-69`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/Item/TriggerOnDamageEnchantmentEffect.cs:38-49`)
- `item -> spell : casts_spell` for `SlateSpellItemData.spellData` / `secondarySpellData`. (`mod/src/Entities/Item/Adapters/ExtractSlateSpell.cs:17-24`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/Item/SlateSpellItem.cs:211-227`)
- `item -> enchantment : grants_enchantment` for `EquipItemData.enchantments` / `builtInEnchantments`. (`.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/Item/EquipItem.cs:164-181,437-450`; `mod/src/Entities/Item/Adapters/ExtractEquipment.cs:12-17`)
- `item -> recipe : teaches_recipe`, `recipe -> item-tag : requires_tag`, and `recipe -> item/status-effect : produces_potion` for recipe wrappers, ingredients, and outputs. (`mod/src/Entities/Item/Adapters/ExtractPotionRecipe.cs:17-33`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/Item/RecipeItem.cs:8-18`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/Item/PotionRecipe.cs:13-39`)

## 7. Slug/redirect recommendation

Use **human slug + stable opaque suffix** as the canonical route token: `/<plural>/<slug>--<id8-or-id12>`. The graph schema already separates `route_path` from `canonical_slug` and already has alias/redirect/disambiguation tables, but today item nodes still write raw ids into both fields and the public item page resolves by id. Add a uniqueness constraint or index on `(entity_type, canonical_slug)` before you switch public routes; use `entity_aliases`/`entity_disambiguations` for name lookup and search, not as canonical routes; and use `entity_redirects` (or a route-token equivalent keyed the same way) for permanent redirects from legacy guid routes and renamed slugs. Never use incrementing collision counters like `restore-health-2`; duplicate names need deterministic id-tailed slugs that survive content set changes across patches. (`pipeline/src/relationships/relationship-graph.ts:4-31`; `pipeline/src/stages/emit-read-models.ts:161-165,207-214,257-264,362-368`; `site/src/routes/items/[id]/+page.server.ts:11-20`)

## 8. Top 5 foreseeable regressions, ranked

1. **Reflection parity inside `StringTooltip.GetValueFromField`.** The game falls back field -> property -> method reflection, applies three percentage transforms plus `oneMinus`, `invert`, rounding, `absoluteValue`, and recursively expands status-effect wrappers; it also has quirks like list handling overwriting rather than joining. If the TS port “cleans this up,” tooltip text will diverge. (`.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/StringTooltip.cs:90-204`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/ModPerSecondEffect.cs:80-88`)
2. **Spell composition indexing and inheritance.** `SpellTooltip` can read from `spellEffectReference.Spells`, but `SpellData.GetTooltip` appends `GetTooltip`/`GetSubTooltips` only from the local `spells` list, and each variable can independently choose primary vs secondary level via `usesSecondaryLevel`. This is easy to reimplement “more consistently” and still be wrong. (`.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/SpellTooltip.cs:39-68`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/SpellData.cs:154-165,173-237`)
3. **Nested leveled wrappers and stack-mode semantics.** `LeveledLeveledStatusEffect` carries `LeveledFloat` level/lifetime plus `StackMode`, and multiple spell/enchantment paths call `GetLeveledStatusEffect(level)` before composing or applying. Flattening that too early will silently change both displayed text and downstream graph facts. (`.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/LeveledLeveledStatusEffect.cs:7-32`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/StatusEffectTooltipSpellEffect.cs:16-21`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/Item/StatusEffectEnchantmentEffect.cs:68-69`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/Item/TriggerOnDamageEnchantmentEffect.cs:41-49`)
4. **Enchantment override and hiding semantics.** `EnchantmentTooltip.targetVars` replaces the whole template for matching items, the branch does not fall back to reflective substitution when `targetVars` exist but do not match, and `hideEffectTooltips` / `hideEnchantmentTooltip` suppress output in different places. This is exactly the kind of behavior a “clean” reimplementation tends to erase. (`.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/EnchantmentTooltip.cs:43-58`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/Item/EnchantmentData.cs:61-80`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/Item/StatusEffectEnchantmentEffect.cs:62-69`)
5. **Master-tooltip completeness, especially term-set application and spell prefixes.** The game has two passes: `StringTooltip.ApplyColors` for tooltip tokens/colors and `ArdenfallMasterData.ApplyColorCodes` for term-set regex/link injection; `SpellData.GetTooltip` also prepends primary/secondary spell prefixes and wraps sub-tooltips in `spellSubEffectColor`. The current pipeline dictionary and translator do not yet model all of that. (`.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/StringTooltip.cs:54-74`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/ArdenfallMasterData.cs:229-268`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/SpellData.cs:223-237`; `pipeline/src/types.ts:187-190`; `fixtures/synthetic/snapshot/master-tooltip.json:1-10`; `pipeline/src/rich-text/rich-text-v1.ts:37-40,79-90,242-270`)

## 9. Anything else missing

- **Recipe-item text parity needs `PotionRecipeManager`, not just `PotionRecipe` and `ArdenfallMasterData`.** The `(Learned)` suffix and the “Learn the potion recipe {0}” description format live on `PotionRecipeManager`, outside the proposed master-tooltip singleton. - The proposal should call out **explicit recursive graph predicates** for `StatusEffectData.modifyStatusEffects`, `SpellData.spellEffectReference`, and recursive enchantment application; otherwise you will compose text correctly but still miss real reverse pages like “status effects modified by this effect” or “enchantments applied by this enchantment.” (`.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/StatusEffectData.cs:124-181`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/SpellData.cs:117-123,154-165`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/Item/TimedEnchantmentEffect.cs:24-29`; `.decompiled/0.0.10.91-63c576261184/csharp/Ardenfall/Item/TriggerOnDamageEnchantmentEffect.cs:41-49`)
